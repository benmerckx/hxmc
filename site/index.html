The Haxe compiler, in Haxe

A faithful port of the Haxe compiler from OCaml to Haxe, faster than upstream, and hxmc: a Haxe target that compiles programs, the compiler included, to machine code and WebAssembly with its own code generator and linkers. No C compiler, assembler, linker or SDK.

Install

From npm, node 22 or later.

npm i -D @hxmc/cli      # then: npx haxe

haxe is the full Haxe command line with hxmc built in: every target works as usual (--js, --interp, ...), and --custom-target hxmc=<out> writes an executable.

-cp src
-main Main
--custom-target hxmc=bin/app
# -D hxmc.target=windows-x86_64   # cross-compile to another target
  • npm installs a native compiler for your platform; where none runs, haxe falls back to a WebAssembly build under node.
  • Libraries install from npm and are found by -lib (lix and haxelib still work).
  • More: docs/using.md.

The target

Any target, from any host.

hxmc writes x86-64 and ARM64 machine code with its own register allocator and linkers (ELF, PE, Mach-O), or a WebAssembly module, with a precise generational collector and threads written in Haxe. Every target cross-builds from Linux or macOS, and hxmc builds itself.

TargetOutput
Linux, x86-64 and ARM64a static executable (musl), or linked against glibc 2.17+ (-D hxmc.libc=glibc); shared libraries
macOS, x86-64 and ARM64an executable; dylibs
Windows, x86-64 and ARM64an executable
Android, ARM64 and x86-64an APK, written without the SDK, or the shared library alone
iOS and its simulatoran app bundle or .ipa, written without Xcode
wasm32-wasia WebAssembly module (exception handling, or the legacy instructions)

Internals: docs/hxmc.md. An experimental app and GUI stack on hxmc lives in a separate repository, universe; hxmc does not depend on it.

Download

Nightly builds of main, with the standard library.

Linuxx86-64ARM64
macOSx86-64ARM64
Windowsx86-64ARM64
haxe -cp src --main Main --interp
haxe -cp src --main Main --js out.js
  • The same arguments as haxe. Set HAXE_STD_PATH to the archive's std.
  • Built by hxmc on Linux, with mbedtls and libuv: sys.ssl and eval.luv work in macros and --interp.
  • macOS quarantines browser downloads: xattr -d com.apple.quarantine haxe.
  • All files: the nightly release.

lix

The Haxe package manager, native.

lix and haxeshim, built by hxmc: one file (about 2 MB) that acts as lix, haxe, haxelib or neko by its name.

Linuxx86-64ARM64
macOSx86-64ARM64
Windowsx86-64ARM64
# Linux x86-64; also lix-linux-arm64, lix-macos-arm64, lix-macos-x86_64
curl -fLo ~/bin/lix https://haxe-in-haxe.ben.mk/tools/lix-linux-x86_64 && chmod +x ~/bin/lix
lix shims     # links ~/bin/haxe, ~/bin/haxelib, ~/bin/neko
# PowerShell, into a directory on PATH; also lix-windows-arm64.exe
curl.exe -fLo C:\tools\lix.exe https://haxe-in-haxe.ben.mk/tools/lix-windows-x86_64.exe
lix shims     # hard links haxe.exe, haxelib.exe, neko.exe

Per project:

lix scope create                # a .haxerc here
lix install haxe 4.3.7          # download it, use it here
lix +lib tink_core              # haxe_libraries/tink_core.hxml
haxe -lib tink_core --run Main  # Haxe 4.3.7 with tink_core
lix download                    # after a clone: what the scope needs

Direction

Boring on purpose.

  • The compiler follows Haxe: its syntax, its tests, its releases.
  • Distribution through npm.
  • Additions only where they never change output: the module cache on disk, fast macros, libraries from node_modules, anything that makes builds faster.
  • The target: live reload on every platform (or hooks for it), more low-level capabilities, a collector that can run between frames, debugging.

The plan: ROADMAP.md, and the discussion in #10.
